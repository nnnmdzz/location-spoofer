# v1.0.5-0009

发布日期：2026-08-12

`v1.0.5-0009` 修复私人签名链路中 App/SDK 硬编码 `personal-main` 与 Worker 实际 Profile Set ID 不一致导致的签名失败，并把项目更新、版本来源和 Profile 选择迁移到 Private Signer v3。

## 私人签名修复

- App 不再编译任何 Profile ID；只保留稳定项目身份 `location-spoofer`。
- 私人自更新由 Worker 返回当前项目的目标 ProjectVersion、允许的 Profile 和默认 Profile，SDK 使用真实 `profile_id` 创建签名 Job。
- 删除 `personal-main` 的客户端约定和默认值，避免 Admin Console/R2 Profile Set 改名后客户端继续发送过期 ID。
- Location Spoofer 的 client token 只用于本项目更新，不再暴露任意 URL/本地 IPA 的通用签名入口。

## 版本与 IPA 来源

- 私人自更新不再由 App/SDK 查询 GitHub 后把 unsigned IPA URL 发送给 Worker。
- Worker 维护 Project → ProjectVersion 目录，并根据 GitHub Release/asset 身份解析签名源。
- 同一版本的源 IPA digest 首次使用时会被锁定；后续内容发生变化会标记冲突并拒绝静默重签。
- “复制公开 unsigned IPA 地址”仍保留，但它是 App 自己的公开 GitHub fallback，与私人签名链路完全分离。

## 协议兼容性

- 本版本使用 Private Signer **v3**，属于破坏性 bug 修复，不兼容旧 `/v2` client contract。
- 旧 `SIGNING_REQUEST_TOKEN` / `personal-main` 配置不作为兼容路径保留。
- 使用私人签名前，服务端必须已经部署 v3 Worker，并为 `location-spoofer` 配置允许/默认 Profile 与新的 scoped Principal token。
- Keychain service 和 Stable Configuration Group 保持不变，因此新的 Worker URL/token 仍保存在原有本机配置槽位中。
